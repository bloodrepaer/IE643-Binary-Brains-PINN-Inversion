# Study 3: hypothesis suites, where the PINN should win

Benchmark families that each test one claim of the form "a PINN should beat the classical adjoint when ...". Every family has a matched control, so a win or a loss can be attributed to the one thing that changed.

- `datasets_v2_pinnwin/`: 57 datasets, families H1-H5 (`generate_pinn_favoured.py`)
- `datasets_v2_pinnwin2/`: 24 datasets, families H6, H7, H9 (`generate_pinn_favoured2.py`)
- `datasets_v2_pinnwin3/`: 6 datasets, family H10u (see below; not generated by a script in this repository)

There is no family H8.

The format is identical to `datasets_v2_rk4_zero/` (`sensors/`, `problem/`, `ground_truth/`, `manifest.json`), so `core/adjoint_inversion.py` and the PINN read these collections unchanged. The manifest adds `family`, `hypothesis`, `role` (test / control), `pair`, `bc_true`, `bc_known`, `source_q`, `source_known`.

## The families

| Family | Hypothesis | What changes | Control |
|---|---|---|---|
| H1 | Sensors very sparse, scattered, off-grid | 3 / 5 / 8 random off-grid sensors, 40 time levels | same field, 50 sensors |
| H2 | Boundary condition unknown | left edge heated (step or ramp) or top edge pulsed; amplitude 0.1 / 0.3 / 1.0 of the IC peak; **BC not given** (H2u) | identical sensor files, BC given (H2k) |
| H3 | Source unknown | a Gaussian heater at (0.62, 0.35), r = 0.06, injecting 0.1 / 0.3 / 1.0 x the IC's heat over the horizon; **source not given** (H3u) | same sensors and noise draw, no heater |
| H4 | Heavy noise, smooth D | noise 10 / 20 / 30 / 50 % | noise 5 % |
| H5 | Long time horizons | Fo = 0.5 / 1.0, 200 time levels, top edge pulsed every Fo 0.05 (known), so longer means more pulses | Fo = 0.2 |
| H6 | More readings, physics fully known | 100 (random pool) and 400 (grid nodes) sensors x 40 times, noise 5 %; A_smooth, E_grf_corrlen_long, G_lowfreq | |
| H7 | Unknown BC with more readings | A_smooth and E_grf; top edge pulsed (0.3) or left edge heated (1.0); 100 and 400 sensors x 40 times, noise 5 %; BC not given (H7u) | identical sensor files, BC given (H7k) |
| H9 | D finer than the adjoint's 16 x 16 control grid, dense data | E_grf_corrlen_short (correlation length 0.03) and D_checkerboard_fine (6 x 6 blocks); 400 nodes x 40 times, noise 1 % | |
| H10u | Unknown BC, very dense data | A_smooth with the left edge heated (1.0) and E_grf_corrlen_long with the top edge pulsed (0.3); 400 and 3,249 sensors x 40 times, noise 0 or 1 %; BC not given | |

Fields: `A_smooth`, `E_grf` and `E_grf_corrlen_long` from the main benchmark, plus a new tier `G_lowfreq` (D = 0.10 + 0.25 (0.6 x + 0.4 (0.5 + 0.5 sin(pi y))), range 0.10 to 0.35). "D smooth and low-frequency" is covered by these field choices inside H1, H4, H5 and H6.

## Fairness rules

- Same solver, grids, IC and noise convention as the main benchmark (RK4 on 129 x 129, inversion on 65 x 65, sigma = eta x RMS of the clean field at 100 random sensors x uniform40).
- "Unknown" means unknown to **both** methods. `problem/*.json` then has `"known": false` and the value a method that needs one must assume (zero edges; f = 0). The true BC and source are only in `ground_truth/` (`bc_true_edges`, `source_true`), for scoring.
- In an unknown-BC problem file the IC's boundary nodes are set to the assumed value, so g(0) does not leak.
- The adjoint, as implemented, cannot leave the BC or source free, so on H2u, H3u, H7u and H10u it runs **misspecified**, with zero edges and f = 0. A stronger classical baseline would add the boundary values or the source as extra unknowns; this one does not, so a PINN win on these families is a win over the standard formulation.
- `validate_pinn_favoured.py` writes `truth_replay_over_sigma`: the TRUE D run through the model each inversion is told. Controls sit near 1; unknown-BC and unknown-source datasets sit well above 1. That gap is the floor the adjoint cannot get under even with the correct D.

## Boundary conditions in the PINN: `core/pinn_inversion_bc.py`

`core/pinn_inversion.py` builds u = 0 on every wall into the network (`bc_win`, `edge_taper`) and adds a zero-BC loss. That is right for the main benchmark but cannot represent a heated wall. `core/pinn_inversion_bc.py` is a copy that reads the BC mode from `problem/*.json`; nothing else changes:

| Mode | When | What the PINN does |
|---|---|---|
| `dirichlet` | all edges 0, known | unchanged: hard zero window + zero-BC loss |
| `dirichlet_soft` | edges non-zero, known (H2k, H5, H7k) | no hard window; L_BC = mean (u(wall, t) - g(t))^2, g from the problem file |
| `free` | `"known": false` (H2u, H7u) | no hard window, no BC loss: u is free on the walls, pinned only by the data |

For an unknown source (H3u) the PINN, like the adjoint, assumes f = 0.

## Files

| File | What it does |
|---|---|
| `generate_pinn_favoured.py` | Builds `datasets_v2_pinnwin/` (H1-H5) |
| `generate_pinn_favoured2.py` | Builds `datasets_v2_pinnwin2/` (H6, H7, H9) |
| `validate_pinn_favoured.py` | Checks a collection before any inversion: every dataset loads, the PINN's problem files exist, and the truth-replay floor; writes `<collection>/validation.csv` |
| `run_pinn_pinnwin.py` | Runs `core/pinn_inversion.py` (or `core/pinn_inversion_bc.py` with `--module`) on a collection: Tikhonov, lambda_reg 2e-4, 1,500 epochs, seed 42 |
| `score_pinnwin.py` | Scores the adjoint and the PINN identically on a collection (relL2(D), replay under the TRUE BC, truth replay, best constant); writes `results/results_pinnwin_scores.csv` or `results/results_pinnwin2_scores.csv` |
| `results/results_pinnwin_scores.csv` | Scores on `datasets_v2_pinnwin` (57 datasets x adjoint, PINN) |
| `results/results_pinnwin2_scores.csv` | Scores on `datasets_v2_pinnwin2` (24 datasets x adjoint, PINN; plus a 32 x 32-control adjoint on the two H9 datasets) |

## How to run

From `extended_studies/`, after `python run.py core/generate_dataset_v2.py`:

```bash
python run.py study3_pinn_favoured/generate_pinn_favoured.py      # 5 to 10 min, deterministic
python run.py study3_pinn_favoured/generate_pinn_favoured2.py
python run.py study3_pinn_favoured/validate_pinn_favoured.py      # checks datasets_v2_pinnwin
python run.py study3_pinn_favoured/validate_pinn_favoured.py datasets_v2_pinnwin2

# classical adjoint
python run.py core/adjoint_inversion.py --data datasets_v2_pinnwin --all --out results_pinnwin_adjoint
python run.py core/adjoint_inversion.py --data datasets_v2_pinnwin2 --all --out results_pinnwin2_adjoint
python run.py core/adjoint_inversion.py --data datasets_v2_pinnwin2 --filter family=H9 --control 32 --out results_pinnwin2_adjoint_c32

# PINN (zero-BC families with the original file, non-zero or unknown BC with the BC-aware copy)
python run.py study3_pinn_favoured/run_pinn_pinnwin.py
python run.py study3_pinn_favoured/run_pinn_pinnwin.py --families H2 H5 --module pinn_inversion_bc
python run.py study3_pinn_favoured/run_pinn_pinnwin.py --data-root datasets_v2_pinnwin2 --out results_pinnwin2_pinn --families H6 H9
python run.py study3_pinn_favoured/run_pinn_pinnwin.py --data-root datasets_v2_pinnwin2 --out results_pinnwin2_pinn --families H7 --module pinn_inversion_bc

# scores
python run.py study3_pinn_favoured/score_pinnwin.py                       # datasets_v2_pinnwin
python run.py study3_pinn_favoured/score_pinnwin.py datasets_v2_pinnwin2
```

`score_pinnwin.py` rewrites the table in `results/` with whatever results are present; the committed tables come from the complete runs.

Scoring uses relL2(D) and RMS replay / sigma through the CN solver **under the true BC** (for H2u and H7u the paired H2k / H7k problem file holds it). Replay under the model the method was told is not a fair score when that model is wrong: on H3u the adjoint replays at 0.99 sigma (median) while its median relL2(D) is 3.3. The CN solver has no source term, so H3u replays use f = 0 and are flagged in `replay_note`.

## Results

### Grid adjoint vs PINN (`results/`)

Lower relL2(D) is better. Replay is RMS / sigma under the true BC (H3u: f = 0).

| Family | Datasets | Adjoint median relL2(D) | PINN median relL2(D) | PINN lower | Adjoint median replay | PINN median replay |
|---|---:|---:|---:|---:|---:|---:|
| H1 sparse sensors | 12 | 0.190 | 0.454 | 0 | 0.98 | 4.01 |
| H2k BC known | 8 | 0.201 | 0.332 | 0 | 0.98 | 2.25 |
| **H2u BC hidden** | 8 | 4.364 | **0.338** | **8** | 14.8 | 2.42 |
| H3k no heater | 2 | 0.149 | 0.451 | 0 | 0.98 | 4.48 |
| **H3u source hidden** | 6 | 3.288 | **0.534** | **5** | 0.99 | 5.64 |
| H4 heavy noise | 15 | 0.122 | 0.447 | 0 | 1.00 | 1.44 |
| H5 long horizon | 6 | 0.092 | 0.671 | 0 | 1.02 | 4.91 |
| H6 more readings | 6 | 0.071 | 0.386 | 0 | 1.00 | 3.19 |
| H7k BC known, more readings | 8 | 0.123 | 0.323 | 0 | 1.00 | 1.87 |
| **H7u BC hidden, more readings** | 8 | 6.514 | **0.323** | **8** | 13.2 | 1.99 |
| H9 fine D | 2 | 0.570 | 0.590 | 1 | 2.86 | 20.9 |

- **Physics hidden (H2u, H3u, H7u; 22 datasets):** the PINN is lower on 21 of 22 (median 0.38 vs 5.0). The misspecified adjoint drives D far from the truth to explain readings its model cannot produce.
- **Physics known (the other 59):** the adjoint is lower on 58 of 59 (median 0.12 vs 0.41) and replays at the noise level; the PINN does not win on sparse sensors, heavy noise, long horizons or more readings.
- **H9:** the PINN is lower on one of the two datasets. A 32 x 32-control adjoint gives 0.477 median on these two datasets, so most of that gap is the 16 x 16 grid's resolution.

### Grid adjoint vs neural adjoint (study 1)

The same 81 datasets were also run with both adjoint representations (`campaign/paired_adjoint_results.csv`, collections `datasets_v2_pinnwin` and `datasets_v2_pinnwin2`): grid lower on 38, network lower on 43; with physics known (59) the network is lower on 36, with physics hidden (22) the grid is lower on 15. The six H10u datasets were run only with the two adjoints, both assuming zero BC (median relL2(D) 5.08 grid, 5.88 neural); no PINN was run on H10u. Their data come from `kaggle_thakur/dataset/data.zip`, which is not in the repository; the results are in `campaign/results/datasets_v2_pinnwin3/`.

## Notes and limitations

- The PINN wins only when the boundary condition or source is hidden **and** the adjoint is forced to assume zero. A classical method that estimates the boundary values or the source would remove that disadvantage; it was not tested.
- Long horizons (H5): the top edge is pulsed with a fixed period (Fo 0.05), so the field stays transient; a steady heated wall would reach steady state by Fo of about 0.2 and later readings would add nothing. At 65 x 65 the adjoint stores at most 800 states x 3,969 nodes, about 25 MB, so memory never binds here; H5 tests accuracy over long horizons only.
- Sensor positions come from the same nested 100-point pool as the main benchmark (3, 5, 8 and 50 sensors are nested). `min_offgrid_over_h` in the manifest is the closest any sensor comes to a 65 x 65 node, in grid spacings.
- One seed per method and dataset.
