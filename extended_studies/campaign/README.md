# campaign: result data

All results and run records of studies 1, 2 and 4 (study 3's score tables are in `../study3_pinn_favoured/results/`). Nothing here is regenerated by running the code; the paths stored inside the CSVs and JSON files (for example `campaign\results\datasets_v2_rk4_zero\...`) are relative to `extended_studies/`, written on the machines that ran the jobs.

## Summary tables (studies 1 and 2)

`summary.csv` is written by `campaign.py summary` from the per-job `metrics.json` files. The other tables were aggregated from the same per-job results; no script in this repository writes them.

| File | Contents |
|---|---|
| `summary.csv` | One row per fit (1,332): the 856 campaign jobs (662 `adjoint_nn`, 186 `grid`, 8 `pinn`) and the 476 reused classical estimates (`grid_historical`); collection, dataset, method, relL2(D), replay, sensor fit, time, flag, path to `metrics.json` |
| `analysis_results.csv` | `summary.csv` plus dataset factors (Fo, protocol, layout, BC/source known) and replay under the true physics |
| `paired_adjoint_results.csv` | Study 1: one row per grid / neural-adjoint pair (662) |
| `paired_adjoint_summary.csv` | Study 1 by physics mode and field |
| `paired_errors.csv` | relL2(D) per dataset for every method: `grid` (run in the campaign), `grid_historical` (existing classical estimate), `adjoint_nn`, `pinn` |
| `primary_neural_comparison.csv` | Study 2: neural adjoint vs neural PINN on 8 datasets |
| `grouped_results.csv` | Median error, replay and time per collection, physics mode and method |
| `effects_Fo.csv`, `effects_eta.csv`, `effects_layout.csv`, `effects_n_sensors.csv`, `effects_n_times.csv`, `effects_protocol.csv`, `effects_tier.csv` | Median error and replay by one dataset factor at a time |
| `density_results.csv` | Rows of `analysis_results.csv` for the extended-density collection (180 grid and 180 neural-adjoint fits) |
| `density_paired_results.csv`, `density_paired_summary.csv` | Study 1 on the 180 extended-density datasets, per dataset and per field and noise level |
| `density_complete_curves.csv` | Error at 5 vs 3,969 sensors, per field, noise and method |
| `density_path_diagnostics.csv` | Selected alpha, iteration caps and replay along the alpha path, per density fit |
| `defect_results.csv`, `defect_details.csv` | Defect detection on F_defects fields (Dice score, detections, per-defect contrast and localisation) |
| `dataset_inventory.csv`, `dataset_parameter_axes.csv` | The seven collections and the values each factor takes |

## `results/`

Per-job outputs, one folder per job:

```
results/<collection>/<job id>/
    run_config.json, summary.csv
    <dataset key>/<method>__s42/
        metrics.json, D_hat.npz, model.pt
```

The job id is the first 16 hex digits of SHA-256 of `"<collection>/<key>/<method>/42"`. Counts: 662 `adjoint_nn`, 186 `grid` and 8 `pinn` fits over the collections `datasets_v2_rk4_zero` (389 datasets), `datasets_v2_density_extended` (180), `datasets_v2_pinnwin` (57), `datasets_v2_pinnwin2` (24), `datasets_v2_pinnwin3` (6), `datasets_v2_density` (4) and `datasets_v2_density_wideic` (2). The small `datasets_v2_density` and `datasets_v2_density_wideic` pilots are referenced by the path columns of `analysis_results.csv`.

## `pilots/` (study 4)

One folder per study-4 version, each with its protocol (`PROTOCOL.md`), pilot record (`pilot.json`, with the SHA-256 of every source file used), input manifest, validation records and results.

| Folder | Content |
|---|---|
| `dense10000_v21_gpu/` | v21, 10,000 sensors: `RESULTS.md`, `primary_matched_neural_comparison.csv`, checkpoints in `artifacts/`, the Kaggle kernel in `kernel/`. `failed_attempt_v1/` is the first kernel package, which failed before training (Windows path separators in its input manifest) and produced no results; the repaired package is in `kernel/`. |
| `dense1000_v22_kaggle/` | v22, 1,000 sensors, 5 % noise; one kernel per arm |
| `noise_density_v23/` | v23, 1,000 sensors at 1 % and 10 % noise: `RESULTS.md`, `noise_comparison_n1000.csv`, `cases/` (cases 03-07 were planned and superseded by v24, not run). `quota_after_v22.json` records the remaining Kaggle GPU quota after v22. |
| `noise_density_v24_1000_7500/` | v24 sweep, the final study-4 result: `SWEEP_REPORT.md`, `paired_cell_summary.csv`, `primary_matched_neural_comparison.csv`, `density_trend.png`, `noise_trend.png`, `cases/case_01`-`case_09`, Colab returns in `colab_returns/` |

In `noise_density_v24_1000_7500/`, the files ending in `_partial` (`SWEEP_REPORT_PARTIAL.md`, `paired_cell_summary_partial.csv`, `primary_matched_neural_comparison_partial.csv`, `density_trend_partial.png`, `noise_trend_partial.png`) and `aggregation_first_attempt_missing_v22_eta.csv` are intermediate versions written before all 12 cells were complete; the files without the suffix supersede them.

## `v24_case_results/`

The raw per-case outputs of the v24 sweep as returned from the Kaggle runs (`r24c0N_v1/`: environment, job status, checkpoints, `D_hat.npz`, metrics) and the two Colab runs (`colab_returns/`). 54 of its files are byte-identical copies of files under `pilots/noise_density_v24_1000_7500/`.
